\begin{abstract}
Causal inference and counterfactual reasoning have recently been given a category-theoretic semantics based on string diagrams and their graphical manipulation (``surgery''). Despite these theoretical advances, there is currently no software support for this approach. In this work, we present a prototype implementation in Julia that enables causal and counterfactual queries to be evaluated on probabilistic models represented as string diagrams. This allows us to compare the categorical approach, both conceptually and empirically, with existing implementations in R and Python. In particular, we show that the use of an explicit diagrammatic intermediate representation can achieve competitive performance while offering greater structural transparency and interpretability.
\end{abstract}

\section{Introduction}
Causal inference studies how actions and interventions change the behaviour of complex systems \cite{pearl2009causality}, answering questions such as ``what is the effect of a drug on recovery?'' that purely statistical association cannot. Central to it is the problem of \emph{identification}: given a causal model and available data, can a target interventional or counterfactual query be uniquely expressed in terms of observable quantities? Under hidden confounding this becomes non-trivial; the classic ID algorithm and its counterfactual extension ID-CF \cite{shpitser2008complete} characterise when identification is possible.

Counterfactuals are an especially expressive class: they ask what would have happened under an alternate intervention, often conditioned on observed evidence. A typical query $P(Y_{x}=y \mid X=x', Z=z)$ asks how the outcome would change if $X$ were set to $x$ when in fact $X=x'$ was observed. Grounded in Pearl's counterfactual semantics \cite{pearl2009causality}, such questions are central to explanation, responsibility attribution, policy evaluation, and fairness.

Recent work, initiated by~\cite{jacobs2019causal} and further developed in \cite{jacobs2021causal,lorenz2023causal,tull2023activeinference,friend2025compositional}, has shown that causal inference can be given a rigorous compositional semantics using category theory, most notably the theory of \emph{Markov categories}~\cite{fritz2020synthetic,jacobs2015} and of \emph{string diagrams}~\cite{intro_to_string_diagram}. In this perspective, a Bayesian network is not merely a graph, but a morphism in a symmetric monoidal category, represented graphically as a string diagram where wires indicate variables and boxes indicate conditional mechanisms. Interventions are then modelled as local rewrites of these diagrams (`surgeries'~\cite{jacobs2019causal}), and counterfactual constructions~\cite{jacobs2021causal} correspond to pairs of string diagrams that share latent sources.

The advantage of this semantics is that it makes structural causal reasoning explicit: rather than manipulating symbolic formulas alone, one works with compositional diagrams whose topology encodes causal constraints, and surgery exposes the local structure of interventions and confounding. It is attractive for tool support in particular, since the same diagrammatic primitives are re-used across model construction, intervention, and simplification.

Despite the growing theoretical prominence of string diagram surgery, there is not yet a single system that implements counterfactual identification directly on this semantics. Existing projects provide complementary functionality — categorical probabilistic libraries~\cite{cho2017efprob}, quantum-circuit tooling~\cite{kissinger2024pqs}, and general string-diagram manipulators (e.g.~\cite{caldwell2026tensorrocq,chyp2024}) — but a focused pipeline for diagrammatic counterfactual identification is still missing. In this work we take the first steps to address this gap. Our contributions are:
\begin{itemize}
    \item We present an implementation of counterfactual identification based on string diagram surgery, realised in Julia with the Catlab ecosystem.
    \item We analyse the concrete challenges of implementing categorical causal semantics, including diagram representation, parallel world construction, and simplification.
    \item We connect the implementation to the broader string-diagrammatic reasoning ecosystem through Chyp export, and outline how the same infrastructure can extend toward richer probabilistic semantics.
    \item We compare our implementation with existing R and Python alternatives, identifying the cases where a categorical approach performs better or worse and clarifying the trade-offs involved.
\end{itemize}

The remainder of the paper is organised as follows. Section~\ref{sec:background} reviews the categorical background and string diagram view of Bayesian networks. Section~\ref{sec:implementation} describes the implementation choices and available functionality. Section~\ref{sec:discussion} compares the tool with existing work and highlights experimental evidence. Section~\ref{sec:conclusion} concludes.

\section{Categorical Background}\label{sec:background}

We work with string diagrams for symmetric monoidal categories carrying a copy--discard--uniform (CDU) structure, the setting introduced for causal reasoning by Jacobs, Kissinger and Zanasi~\cite{jacobs2019causal,jacobs2021causal} and closely related to Markov categories~\cite{fritz2020synthetic}. This section fixes the diagrammatic vocabulary that the implementation in Section~\ref{sec:implementation} manipulates directly.

\paragraph{Causal Models as String Diagrams.}
Such a category equips every object $A$ with a \emph{copy} map $A \to A\otimes A$, a \emph{discard} map $A \to I$ to the monoidal unit, and a \emph{uniform} state $I\to A$~\cite{jacobs2021causal,jacobs2015}; the uniform state, which samples a variable independently of its causes, is what makes interventions expressible. Morphisms are drawn as \emph{string diagrams}~\cite{intro_to_string_diagram}: wires denote variables, boxes morphisms, sequential composition stacks boxes and the tensor places them side by side. A \emph{channel} is a morphism $f:A\to B$ read as a conditional $P(B\mid A)$; a \emph{state} $I\to A$ is a distribution and an \emph{effect} $A\to I$ its dual, the canonical one being discard. A morphism is \emph{deterministic} when it commutes with copying; we use \emph{sharp states} (fixing a variable to a constant) and \emph{sharp effects} (constraining a wire to an observed value). In a Bayesian-network diagram a copy map exposes a variable as an observed output, while discarding a wire marginalises a latent one.

In this language a structural causal model is assembled compositionally. Each endogenous variable $X$ with parents $\mathrm{pa}(X)$ becomes a \emph{mechanism}
\[ f_X : \Big(\textstyle\bigotimes_{Y \in \mathrm{pa}(X)} Y\Big)\otimes U_X \;\longrightarrow\; X, \]
a box that takes the parent wires together with a fresh exogenous noise source $U_X$ (a state $I\to U_X$) and produces the wire $X$. Giving each mechanism its own noise source factors all randomness into the exogenous states, leaving the mechanisms deterministic---the property that later lets distinct worlds share the same randomness. Wiring each mechanism's output into the inputs of its children---inserting copy maps wherever a variable feeds several children---yields a single string diagram whose denotation is the joint distribution (the running example is shown in Figure~\ref{fig:running-example}). Two structural advantages follow: conditional-independence (d-separation) properties surface as diagrammatic connectivity, and, crucially for us, interventions become \emph{local} rewrites rather than global symbolic substitutions.

Latent confounding is treated through \emph{Acyclic Directed Mixed Graphs} (ADMGs), whose bidirected edges $X\leftrightarrow Y$ record a shared hidden cause. Mirroring the implementation's compilation step, each bidirected edge is \emph{rootified}: it is replaced by an explicit latent root state feeding both $X$ and $Y$ through a copy map, turning implicit confounding into a shared exogenous source.

\paragraph{Surgery and Counterfactuals.}
An intervention $\mathrm{do}(X=x)$ is modelled by \emph{string diagram surgery}~\cite{jacobs2019causal,jacobs2021causal,lorenz2023causal}: the wires entering $f_X$ are \emph{cut}---the incoming parents are discarded---and $X$ is instead supplied by a sharp state $\mathsf{do}(X{=}x):I\to X$ fixing it to the constant $x$ (Figure~\ref{fig:re-pw}). Categorically this replaces a channel by a constant morphism; graphically it severs $X$ from its causes while leaving the rest of the diagram intact, so the resulting diagram denotes the interventional distribution $P(\,\cdot \mid \mathrm{do}(X{=}x))$.

Counterfactual queries such as $P(Y_x \mid X{=}x',\,Z{=}z)$ compare what \emph{did} happen with what \emph{would have} happened under a different intervention, and so require several worlds to coexist. They are captured by a \emph{parallel-world} (multiverse, the ``twin'' construction of~\cite{jacobs2021causal}): the model is duplicated once per world, surgery is applied only in the intervened worlds, and---the key point---the exogenous noise sources are \emph{shared} across worlds rather than re-sampled. Diagrammatically the latent state is copied into every world (Figure~\ref{fig:re-pw}), so the worlds remain coupled through their common randomness; this is exactly the parallel-world semantics of counterfactual identification~\cite{pearl2009causality,shpitser2008complete}. Observed evidence ($X=x'$, $Z=z$) is imposed by attaching sharp effects to the corresponding output wires.

Whether a counterfactual query is \emph{identifiable}---expressible purely in terms of the observational distribution---is decided by the ID-CF algorithm~\cite{shpitser2008complete}. After surgery and simplification, the diagram decomposes into maximal confounded components, the \emph{c-components} (or districts) of the ADMG; their diagrammatic counterparts are the \emph{R-fragments} that the implementation extracts and rewrites. This decomposition makes plain why some queries are identifiable and others are not: identification succeeds exactly when every fragment's exogenous noise can be absorbed into a consistent, observable expression.

\section{Implementation}\label{sec:implementation}

We implemented the approach in Julia on top of the Catlab ecosystem~\cite{catlab}, which provides a computational realisation of symmetric monoidal categories through \emph{wiring diagrams}(the concrete Catlab data structure used to implement the abstract structure of a string diagram). The whole computation manipulates a single kind of object: a Catlab \texttt{WiringDiagram} in which boxes are mechanisms (morphisms) and wires are variable dependencies. Each box carries a symbolic name encoding its role---\texttt{f\_X} for a mechanism, \texttt{PU\_X} for an exogenous source, \texttt{do\_X=x} for an intervention (a \emph{sharp state}), \texttt{obs\_X=x} for an observation (a \emph{sharp effect}), \texttt{c\_X} for a deterministic constant mechanism---so that surgery and identification are realised uniformly as rewrites on named boxes and their wiring.

\paragraph{Pipeline and Artifact.}
Identification is driven by a single entry point, \texttt{identify\_counterfactual} (alias \texttt{run\_cf\_pipeline}) in \texttt{src/id\_cf.jl}, which executes five stages, timing each independently and exporting an intermediate diagram after every stage (dashed arrows below mark the Chyp trace):

\begin{enumerate}
    \item \textbf{ADMG compilation} (\texttt{src/admg\_compile.jl}). An input Acyclic Directed Mixed Graph (ADMG) is \emph{rootified}---each bidirected edge $X \leftrightarrow Y$ is replaced by a fresh latent root feeding both endpoints---and then compiled by \texttt{graph\_b\_to\_scm} into a base structural diagram with one mechanism box $f_V : (\mathrm{pa}(V), U_V) \to V$ and one exogenous source $PU_V$ per variable.
    \item \textbf{Parallel-world construction} (\texttt{src/build\_multiverse}). The base diagram is lifted into a multiverse diagram by duplicating each mechanism box once per world while \emph{sharing} the exogenous source boxes across all worlds---the diagrammatic counterpart of shared exogenous noise. An intervened variable splits into a discarded sink and a fresh \texttt{do\_X=x} source; an observed variable receives an \texttt{obs\_X=x} sharp-effect box.
    \item \textbf{Simplification} (\texttt{src/simplify\_cf.jl}). Four rewrite passes reduce the diagram to canonical form: pruning discarded branches and dead boxes, separating sharp effects from copy/fan-out, merging deterministic mechanisms with identical input sources, and absorbing exogenous noise by replacing each $f_X$ with a deterministic constant mechanism $c_X$.
    \item \textbf{ID-CF identification} (Step~4, \texttt{src/id\_cf.jl}). The simplified diagram is decomposed into \emph{R-fragments}---the diagrammatic counterpart of c-components (districts) in ADMGs---and each fragment is rewritten by case analysis into an interventional probability box $P(C_l, F_l^{out} \mid \mathrm{do}(D_l), \mathrm{do}(F_l^{in}))$. A residual unabsorbed exogenous source signals a non-identifiable query.
    \item \textbf{Expression output} (Step~5, \texttt{id\_cf\_step5}). The resulting probability boxes are parsed into a small expression tree and rendered as a LaTeX formula, with optional algebraic simplification (e.g.\ dropping vacuous interventions and eliminating normalised summations).
\end{enumerate}
The remaining modules support this pipeline: \texttt{src/bn\_import.jl} and \texttt{tools/\allowbreak import\_bn\_to\_admg.jl} ingest external Bayesian-network files (\texttt{.bif}/\texttt{.net}) as ADMGs; \texttt{src/chyp\_export.jl} serialises any diagram to the Chyp format~\cite{chyp2024} for inspection; and \texttt{src/utils.jl} provides the shared box predicates and graph utilities (topological ordering, signature matching). The command-line driver \texttt{src/run\_demo.jl} and the worked commute example in \texttt{src/main.jl} exercise the full pipeline.

\paragraph{Data Structures and Design Decisions.}
The implementation exposes two interfaces. \texttt{identify\_counterfactual} handles counterfactual identification and returns symbolic probability formulas, whereas \texttt{infer\_causal\_effect} handles comb-disintegration causal inference and returns numerical interventional distributions.

Causal models are described by an \texttt{ADMGModel} (directed and bidirected edge lists), which rootification turns into a \texttt{ConfoundedModel} (directed edges plus a map from each latent root to the variables it confounds). A \texttt{CounterfactualQuery} specifies, per world, the interventions, observations, and output variables. From the simplification stage onwards every state is a Catlab \texttt{WiringDiagram}, and identification proceeds entirely by pattern-matching on box names and rewiring---there is no separate symbolic graph representation. Final expressions are built over a small term language (atomic probability factors, products, sums, and fractions) so that identifiable queries are reported as algebraic formulas matching the output style of existing identification tools, and non-identifiable queries report the stage and box at which absorption failed.

Three decisions characterise the design. First, a single diagrammatic representation is used end to end, so surgery, simplification, and identification are all rewrites on the same object rather than transformations between distinct data models. Second, the pipeline keeps every intermediate stage explicit and exports it to Chyp, making each transformation step inspectable---in contrast to symbolic tools where decomposition and simplification are internal. Third, the stages mirror the theoretical algorithm one-to-one, so each can be tested and optimised independently; the test suite in \texttt{test/} covers ADMG compilation, multiverse construction, simplification, R-fragment partitioning, and expression generation as separate module-level test sets.

\paragraph{Comb-Disintegration Causal Inference Extension.}
In addition to counterfactual identification, the prototype includes a scoped causal-inference extension based on comb disintegration. This part of the tool is exposed through \texttt{infer\_causal\_effect}, rather than \texttt{identify\_counterfactual}. The user provides a Catlab string diagram, a finite observational joint distribution, and a comb structure specified by four groups of variables: observed context \(A\), interventions \(X\), bridge variables \(B\), and outcomes \(C\). The intended query has the form
\[
P(C \mid A, \mathrm{do}(X)).
\]
The tool checks whether the supplied diagram admits the required comb decomposition and, if so, computes the interventional distribution numerically from the joint table.

This extension is demonstrated on a small smoking example and a larger HEPAR2-based clinical example---for instance, how chronic hepatitis would be distributed under interventions on hospital, surgery, and choledocholithotomy history, with injections and transfusion as bridge variables. The full HEPAR2 graph is used for structural validation, while the numerical computation currently uses a finite synthetic joint table over the selected variables.

At present the diagram and the probability table are separate inputs: the diagram validates that comb disintegration is applicable, while the joint table supplies the numbers. This is a practical limitation rather than a theoretical one---the implementation treats Catlab diagrams as structural objects (names, wires, dependencies) rather than executable probabilistic programs. A more complete version would attach a stochastic channel to each mechanism box and compose them along the diagram to obtain the joint distribution directly, avoiding the separate table.



\paragraph{Orienting and Running the Tool.}
For first-time users the recommended entry point is \texttt{src/run\_demo.jl}: it loads a model and a counterfactual query, calls \texttt{identify\_counterfactual}, and prints whether the query is identifiable together with the resulting probability expression. Inputs live in \texttt{examples/admg\_models/}, \texttt{examples/string\_diagrams/}, and \texttt{examples/queries/}; a typical run selects a model and a matching query and inspects the printed result, with optional trace files under \texttt{trace/} exposing the intermediate stages. The comb-disintegration examples in \texttt{examples/causal\_inference/} are run the same way through \texttt{infer\_causal\_effect}---supplying a diagram, a joint table, and the four variable groups---returning a numerical interventional distribution such as \(P(C \mid \mathrm{do}(S))\) in the smoking example.

\paragraph{Worked Example.}
We use a commute scenario as a worked example to illustrate the intermediate representations produced by the implementation. The model describes a daily travel setting with variables \(W,T,M,L,Y\), representing weather, departure time, mode of transport, lateness, and final work performance. 

The counterfactual query asks: for someone who actually left at time \(t'\) under weather condition \(w\), what would their work performance have been if they had left at time \(t\), while also incorporating additional behavioural evidence that, under the same weather, they would use transport mode \(m\)?

\section{Empirical Evaluation}\label{sec:discussion}
We evaluate the prototype along two dimensions: correctness and runtime performance. Correctness is assessed through a differential testing harness against the reference R implementation \texttt{cfid}~\cite{cfid_package}, the reference R implementation of ID-CF on ADMGs, while runtime performance is measured against both \texttt{cfid} and the Python \texttt{y0} library. This separation is important: the correctness harness first checks that the implementation returns verdicts consistent with an established counterfactual-identification tool, and the runtime benchmarks then measure the cost of obtaining those results.

\paragraph{Differential correctness testing.}
Before measuring speed, we first run a differential correctness harness in \texttt{comparisons/correctness/}. The harness generates counterfactual identification problems, translates each case into both the Julia input format and the R \texttt{cfid} input format, and compares the ID/FAIL verdicts returned by the two tools.

The corpus contains structured benchmark cases and randomly sampled bow-free ADMGs over 5--8 nodes. Each random graph is paired with a generated conditional counterfactual query, and cases that reduce to ordinary single-world interventional queries are filtered out. The comparison uses \texttt{cfid} version 0.1.9 and the interventional-data setting, matching the current scope of the implementation.

\paragraph{Runtime benchmarking.}
Having established a high level of cross-tool agreement, we next compare runtime performance. We evaluate the prototype against \texttt{cfid} and the Python \texttt{y0} library. The benchmark harnesses live in \texttt{comparisons/\allowbreak runtime/} (\texttt{julia\_\allowbreak benchmark.jl}, \texttt{r\_cfid\_\allowbreak benchmark.R}, and \texttt{python\_y0\_\allowbreak benchmark.py}); all timings are warm medians over repeated executions on a standard desktop. On the standard benchmarks (Table~\ref{tab:speedup}, top), the categorical tool is consistently faster than R \texttt{cfid}: by roughly $2.7\times$ on the small \texttt{drug} and \texttt{party} queries, and by $86\times$ on the larger \texttt{hepar2\_conditional} network. The comparison with Python \texttt{y0} is more mixed. On the small \texttt{drug} and \texttt{party} examples \texttt{y0} is faster, suggesting that a direct graph-level implementation has lower overhead on small queries; but on the larger \texttt{hepar2\_conditional} benchmark Julia is about $22\times$ faster, indicating that the explicit simplification pipeline becomes more beneficial as the model grows.

A stage-level breakdown explains this behaviour. The dominant cost in the Julia pipeline is the explicit \emph{simplification} stage---in the \texttt{drug} benchmark it accounts for most of the runtime---while identification itself (Steps~4--5) is comparatively lightweight; R \texttt{cfid}, by contrast, exposes the main computation through the single \texttt{identifiable} call. The categorical method therefore trades a heavier simplification phase for a very light identification phase, which pays off when simplification substantially reduces the later identification problem, especially on larger or structurally favourable graphs.

The synthetic families expose this structure-dependent behaviour more clearly (Table~\ref{tab:speedup}, bottom). On \texttt{chain}, \texttt{fanin}, and \texttt{dense}, Julia is faster than R \texttt{cfid}, with speed-ups of $6.13\times$, $3.79\times$, and $2.34\times$, respectively. Compared with Python \texttt{y0}, Julia is faster on \texttt{chain} and \texttt{dense}, and roughly comparable on \texttt{fanin}. These results suggest that the diagrammatic pipeline is competitive on sparse and moderately connected graph structures.

The main limitation appears on the heavily confounded \texttt{chain\_bi} family. Here the result reverses: Julia is slower than both R \texttt{cfid} and Python \texttt{y0}, with ratios of $0.38\times$ and $0.04\times$, respectively. The reason is that bidirected confounding greatly increases the cost of diagrammatic simplification. The identification phase remains small, but the preprocessing cost dominates the total runtime.

\section{Discussion}\label{sec:conclusion}

We have presented a prototype for counterfactual identification on Bayesian networks built directly on the categorical semantics of string-diagram surgery, realising the full ID-CF pipeline as rewrites on Catlab wiring diagrams with a Chyp trace exported at every stage. The evaluation shows this is not merely feasible but competitive: the tool reproduces \texttt{cfid}'s results and is substantially faster on sparse and moderately dense models, at the cost of an explicit simplification phase that becomes the bottleneck on densely confounded graphs.

The current implementation has four main limitations, each pointing to a direction for future work.
\begin{itemize}
    \item \textbf{Scope:} the tool targets the ID-CF setting for discrete graphical models, resting on the usual causal-model assumptions (causal sufficiency, correct specification), and does not yet cover causal discovery or continuous latent-variable models; the bidirected-edge abstraction may also miss some hidden dependencies. A natural next step is to broaden the query class and integrate with probabilistic inference engines.
    \item \textbf{Structure-dependent performance:} the simplification stage relies on repeated full-graph traversals and dominates runtime, so on dense and especially bidirected-confounded graphs (e.g.\ \texttt{chain\_bi}) this preprocessing cost can erase or reverse the identification speedup. Incremental rewriting and more efficient wiring-diagram data structures would remove these repeated scans.
    \item \textbf{Visualisation:} Chyp export aids inspection but supports a limited character set (unsupported symbols are mangled in labels, most acutely in identification outputs) and does not scale to large diagrams; a dedicated interactive string-diagram visualiser, supporting splicing, intervention, and rewrite operations, would address this.
    \item \textbf{Verification and interoperability:} the explicit intermediate diagrams make every rewrite step inspectable, but the steps are not yet formally verified and there are no native integrations with other toolchains. Future work includes formal verification and integration with richer categorical and probabilistic toolchains---for example EfProb~\cite{cho2017efprob}---and connections to causal representation learning and reinforcement-learning pipelines.
\end{itemize}
